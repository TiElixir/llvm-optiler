# Decisions and deviations from PLAN.md

PLAN.md stays the product spec. This file records where the build differs from it, and why.

1. **Attribution is `perf | probe | est`.** PLAN.md 8.2 has only `perf | est`. Probe mode builds a second, instrumented `model_probe.so` with a cycle-counter timer around every top-level loop nest, so measured per-op shares exist on machines without `perf`. The headline runtime always comes from the uninstrumented build.
2. **Extra dependencies (approved by the user):** `httpx` (FastAPI TestClient), `vitest`, `@playwright/test`. Fonts are asked about separately in M2.
3. **Native build:** `opt -passes='default<O3>'`, then `llc -O3`, then `clang -shared` (link only). O3 runs once, and the `asm` stage is the disassembly of the exact `.so` that runs.
4. **Measured allocations.** The MLIR memref alloc/free helpers are implemented in `backend/runtime/optiler_rt.c`, so `alloc_count` and `peak_bytes` are measured. The static liveness walk (8.3) remains as the `est` value per stage.
5. **"Measurably faster"** means child p90 < parent p10 and ratio >= 1.05. Otherwise a finding shows "no measurable change", or "slower xN" when the child is slower.
6. **Tailwind v4.** Tokens live in `tokens.css` and are mapped with `@theme inline`; this plays the role of `tailwind.config` in PLAN.md 4.4. Components never use raw hex.
7. **The demo narrative is a hypothesis.** If measurement on `attention_block` shows a different top finding than "unfused softmax", the demo text or template dims change to fit the data, never the reverse (Rule 2).
8. **Python 3.12** (venv via `uv`). The system Python is 3.14, which torch-mlir wheels do not support.
9. **Own git repo** in `MLIR_v2/`, at most 12 planned commits, one per milestone after its checks pass.
10. **Project-local LLVM 23.1.5.** `toolchain/llvm` (gitignored) from the official release tarball via `scripts/setup_llvm.sh`; the system LLVM is never modified (a partial `llvm` upgrade broke `opt`, and a full `-Syu` was declined).
11. **D3's first fix is loop interchange + removing `affine-loop-fusion`**, not tile-and-vectorize: it was measured at 13.6x on `matmul_relu` (docs/toolchain.md) and needs only a three-line transform script. Tile+vectorize stays an option if a template needs it.
12. **Large constants are elided in stored snapshots** (display only); `changed` hashes the full text.
13. **The frontend is plain HTML, CSS and vanilla JS (user decision, replaces the React/Vite/Tailwind/CodeMirror plan in PLAN.md 11b).** No bundler and no npm dependencies; `uvicorn backend.api.app:app` serves the UI and the API from one process. One page, no separate start screen. JS is used only where there is interaction (the pass map, the inspector, and later the lineage SVG in the Pipeline Map). The decorative wordmark and token-field background from PLAN 4.2/4.3 are dropped: it is a tool, not a landing page. Source editing is a plain `<textarea>`; IR is a highlighted `<pre>`; diffs render the API's unified diff. Frontend tests use node's built-in runner (`node --test frontend/test`), the browser smoke test (M7) uses the already-installed global Playwright.
14. **Fonts:** the reference site's sans (Chalet London) is commercial and is not shipped; the stack falls back to Geist / Inter Tight / system fonts. Source Code Pro (OFL) is the measured mono face and falls back to system mono. No font files are vendored (asks first, PLAN rule 5).
15. **Thinking orbs (user request).** The processing indicator is the MIT-licensed canvas engine from github.com/RareFormLabs/thinking-orbs, vendored in `frontend/vendor/thinking-orbs` (types stripped, license kept) behind a ~60-line vanilla wrapper `frontend/js/orb.js`. Each pipeline phase has its own orb; no Vue/npm.
16. **Probe-timing attribution was not built.** perf works here (LBR call graphs), so attribution is `perf` with a labeled static `est` fallback (FLOPs and bytes per linalg op, calibrated per machine). The estimate ranks lines correctly but runs about 3x low in absolute time because the calibrated scalar rate (5 GFLOP/s) exceeds what the pipeline's loops reach (1-3).
17. **Measured lead finding on attention_block** is the scalar `q @ k^T` matmul (45% of runtime), not softmax (2%): the demo narrative follows the data (decision 7).
18. **Detectors (M5).** D1 (unfused elementwise chain, fix: enable fusion), D2 (temporary materialized then copied) and D3 (hot matmul loop not vectorized, fix: interchange + no affine fusion) each emit only when certain. D3 judges the *hot* instructions of a line (perf), not every instruction, because a transpose on the same line can vectorize while the matmul does not. D2 offers no fix: `eliminate-empty-tensors` was tried on the copy_cat model and removed nothing. Findings below an estimated 1.05x are dropped.
19. **Fixes and verdicts (M6).** A fix is data (`backend/fixes/registry.py`); applying one creates a child run with the patched pipeline, reusing the parent's captured model. The finished child writes a measured verdict onto the parent's finding: `verified` only if the child's p90 is below the parent's p10 and the ratio is at least 1.05x, otherwise "no measurable change", "slower" or "broke correctness". On attention_block the D3 fix measured 11.6x (estimate 2.1x). The accent color marks exactly one thing: the selected finding's `fix` button, or its `verified` badge.
20. **Static files revalidate** (`Cache-Control: no-cache`): the UI is plain files that change between versions.
